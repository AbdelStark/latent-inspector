EUPE vs DINOv2 / I-JEPA / V-JEPA 2

A latent-inspector comparison. Abdel (@AbdelStark) · April 2026 · Single-image, fixed-prompt benchmark · raw JSON report

EUPE is a very different kind of vision encoder from DINOv2, I-JEPA, and V-JEPA 2, and when you measure the representations side-by-side on the same image, every metric tells the same story: EUPE collapses to a small number of dominant axes, lives in a qualitatively different geometry, and barely agrees with any SSL-only model about which patches are near each other.

This page is a public writeup of the observations I mentioned in my reply to Saksham's question about what I saw when I added EUPE to the latent-inspector model registry. All numbers below come from a single reproducible run of latent-inspector compare on the canonical elephant_sample_image.jpg, with the full JSON dumped alongside this page so anyone can verify. Caveats about the HuggingFace → ONNX export path are at the bottom.

Headline: EUPE is off-manifold from the three SSL-only models

The short version, before the table:

  • CKA against the reference models: near zero. EUPE↔DINOv2 = 0.044, EUPE↔V-JEPA 2 = 0.038, EUPE↔I-JEPA ≈ 0.000. By comparison, the three SSL-only models score CKA 0.27–0.36 between themselves.
  • k-NN agreement on which patches are similar: ~10%. EUPE's 10-nearest-neighbor structure overlaps the reference models at 8.9%–13.2%, versus 20%–28% among the three SSL-only models.
  • Patch isotropy collapses by ~30×. DINOv2 / I-JEPA sit at isotropy ≈ 0.79–0.80, V-JEPA 2 at 0.68, and EUPE at 0.026. EUPE's patches don't spread around a sphere — they live along a handful of dominant axes.
  • Variance concentrates in ~12–17 dimensions out of 768. EUPE needs only 12 principal components to capture 90% of variance; the others need 22–38 (out of 1024–1280). Its effective rank is 17 versus 44–64 for the reference models.
  • Spatial coherence almost saturates. EUPE's spatial coherence is 0.985 (neighboring patches are nearly identical in representation); the references are 0.44–0.57 (more local variation).
The interpretation I'd offer (and would love to have corrected if it's wrong): this looks like the geometric signature of multi-teacher distillation into a capacity-constrained student. EUPE is 86 M parameters (ViT-B/16) trying to serve multiple specialized teachers at once; the representation has to pick a small number of task-relevant axes and compress hard along them. That's consistent with everything the numbers show: low effective rank, top-heavy variance, high spatial coherence, very low isotropy, and near-orthogonal alignment with models whose objective is to spread the representation across the manifold.

Two things to notice. First, the three SSL-only models form a cluster — they each have CKA 0.27–0.36 with each other, which is "weak but non-trivial structural agreement". Second, EUPE is the lone outlier at CKA < 0.05 against all three, and essentially zero against I-JEPA. That's the kind of CKA number you'd expect between a vision encoder and, say, a language model — not between two vision encoders trained on natural images.

k-NN overlap is a structural test that's insensitive to the choice of coordinate frame — it only cares about whether which patches are similar to which other patches agrees across models. EUPE disagrees with the reference models on 87–91% of the k=10 neighborhoods, against 72–80% disagreement among the three SSL-only models. This matches the CKA finding: EUPE is organizing the patch space along different axes.

Dropped metrics (with reasons)

  • CLS cosine similarity: unavailable between EUPE and the references because the CLS dimensions differ (768 vs 1024) AND because I-JEPA / V-JEPA 2 don't expose a CLS token in the first place. EUPE's own CLS L2 norm is 56.5 (vs DINOv2's 46.3).
  • Mean patch correspondence: unavailable between models with different embedding dimensions. This drops all EUPE pairs and all cross-family pairs.
  • Patch-grid alignment: EUPE has a 14×14 patch grid (196 tokens), the others have 16×16 (256 tokens). latent-inspector aligns by taking the first 196 shared patches; if you care about this, the "note" field in the JSON spells it out per pair.

What I would watch if I were you

I want to be explicit about what I don't know, and what would sharpen the interpretation:

  1. Is the low-rank/high-anisotropy signature consistent across many images, or an artifact of one particular photograph? The compare here is on one image (elephant). Running the full latent-inspector benchmark across the sample set would tell us whether the effective-rank-17 and the isotropy collapse are invariants of the encoder or dependent on content.
  2. Do EUPE's top-12 principal components still carry the teacher-relevant signal? If I projected EUPE tokens onto a DINOv2 subspace (or vice versa) and measured classification/retrieval accuracy, the compression might be "lossless for the teachers' tasks" while looking dramatic on generic spectral metrics. That's a natural follow-up experiment.
  3. What does EUPE look like on downstream tasks relative to its compression? The headline numbers here are measuring representation geometry, not representation quality. Those are related but not identical. EUPE's compressed representation might actually be better for the specific tasks it was distilled for, even though it looks like an outlier by spectral metrics that reward spreading the representation.
  4. How does EUPE compare against other distillation-family models? I don't have, say, a multi-teacher BEiT variant or a CLIP-distilled model in the registry yet. Those would be the right control group to test "multi-teacher distillation → compressed representation" as a general pattern.

Caveats about the ONNX export path

Because I mentioned it in my reply to Saksham and I want to be honest about it: I exported EUPE from the HuggingFace release to ONNX myself, and it is in principle possible that some of what I'm seeing is a conversion artifact rather than a property of the trained model. The relevant details:

  • The ONNX file is structural only; no quantization, no graph surgery beyond what the standard torch.onnx.export + optimum-onnx path does.
  • The CLS and patch outputs go through latent-inspector's normal extraction path — same code that handles DINOv2, same preprocessing normalization, same token-grid reshape.
  • The evidence against a conversion bug: the extreme numbers are consistent across six independent metrics (effective rank, RankMe, top-10 variance, 90%-components count, isotropy, spatial coherence). If ONNX were producing garbage I'd expect one or two metrics to go weird, not every metric to line up with the "compressed representation" interpretation.
  • The evidence for caution: I haven't reference-checked the ONNX export against the PyTorch model's raw outputs on a fixed image. I can do that (and I will, if Saksham or anyone from the EUPE team wants the numbers).

Everything in this writeup is reproducible. The raw JSON is at eupe-compare.json. The code is at github.com/AbdelStark/latent-inspector. The exact command is:

cargo build --release
./target/release/latent-inspector compare docs/assets/img/samples/elephant_sample_image.jpg \
  --models dinov2-vit-l14,ijepa-vit-h14,vjepa2-vitl-fpc2-256,eupe-vit-b16 \
  --output /tmp/eupe-compare \
  --format json
